## Classification policy

Every distinct dataset under the source repository's `data/` and `Tables/`
directories is represented in the Explorer or preserved in a catalogued source
archive. Shapefile sidecars, byte-identical duplicates, rendered companion files,
and documentation are accounted for in the source manifest rather than presented as
independent measurements.

The Explorer distinguishes these classes:

- **Observational:** source files presented as site geometry or EO observations.
- **Methodological:** grids and other analysis structures rather than measurements.
- **Example:** source files explicitly stored under an examples directory.
- **Synthetic:** values generated by source code using random-number functions and
  fixed seeds. These are never described as sensor observations.
- **Unverified:** source records whose provenance, coordinates, repeated content, or
  CRS cannot support scientific interpretation.

## Raster imports

- `data/processed/s2_to_rm.tif` was losslessly repackaged as a Cloud Optimized
  GeoTIFF. The 15 other copies of this file have the same SHA-256 hash and are
  represented once, not mislabeled as separate airborne, thermal, PRISMA, EnMAP, or
  CHIME observations.
- All six files under `data/rasters/` are imported as explicitly synthetic
  method-development products. The source script
  `scripts/1-generate_multiresolution_rasters.R` creates them with `runif()`,
  `rnorm()`, and fixed random seeds.
- Source EnMAP-like and PRISMA-like files are byte-identical and share one imported
  COG while retaining separate catalog entries for their source identities.
- The tracked synthetic thermal raster contains only nodata values. This condition
  is preserved and reported rather than repaired or filled.

## Vector imports

- All correctly georeferenced shapefiles and GeoJSON files were converted or copied
  to GeoJSON in EPSG:4326.
- The 10,302-cell PRISMA grid and 110-cell FLEX grid are retained as methodological
  analysis layers.
- Two shapefile datasets have coordinates that conflict with their declared CRS or
  named site: `alfaalfa_test` and `Areas_olive_pistacchio`. Their original components
  are preserved as ZIP archives and catalogued, but are not placed on the map because
  doing so would invent a corrected location.

## Table imports

- Both olive layout CSV files are copied unchanged.
- All three sheets in `Example_olives.xlsx` are converted to CSV without changing
  cell values.
- Nine `HYDRA_CRE_20260505_scoring_v1..csv` files are byte-identical despite being
  placed in unrelated field and metadata folders. One copy is retained and labeled
  unverified. Its values are not treated as measurements, diagnoses, or valid
  coordinates.

## Source projects and companion files

The two QGIS project files are preserved as source archives. Rendered `.qmd` HTML
companions, readme files, shapefile components, and raster-statistics sidecars are
listed individually in `source-manifest.json` with their disposition.

## Known metadata gaps

The source repository does not provide a data license file despite referring to one
in its README. Acquisition dates, product identifiers, processing baselines,
calibration records, field protocols, positional uncertainties, and processing
details are incomplete for several assets. Missing values remain `not provided`.
No browser-side vegetation-index calculation is authorized for imported datasets.
